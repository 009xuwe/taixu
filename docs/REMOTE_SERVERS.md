# 远程 Linux 执行环境

在「Linux 系统管理」中点击「添加系统」，可选择本地安装或连接远程服务器。

远程连接需填写名称、主机/IP、SSH 端口、用户名和已存在的远程工作目录。服务器必须启用 SSH 与 SFTP，并允许该用户访问工作目录。支持密码认证，以及粘贴或通过系统文件选择器导入 PEM/OpenSSH 私钥；加密私钥可填写口令。

首次连接会在发送认证凭证前显示 SHA-256 主机指纹。与服务器提供的指纹核对并确认后，应用验证认证及工作目录，测试成功不会保存配置；点击保存后验证并保存配置，不改变当前主系统。在系统列表中点击「设为主系统」才会切换新会话使用的系统。此后固定该指纹，发生变化时拒绝连接；需要核验后移除旧配置并重新添加。

选择默认远程环境后新建对话。首次构建模型上下文时固定执行环境，后续 `base`、`process`、`read`、`write`、`edit` 及 MCP STDIO 都使用同一服务器；子任务继承服务器和工作区，但独立管理连接和进程。切换全局默认不会改变已绑定会话。切回本地环境或设置本地主系统后，新会话使用手机上的 Linux。

未关联项目的远程会话使用配置的工作目录。项目 `/workspace/demo` 映射为 `<远程工作目录>/demo`，子目录需已存在；不会复制手机项目文件。文件工具限定在该会话的远程工作区，命令则具有 SSH 用户在服务器上的实际权限。运行前沿用已有审批和 PLAN 规则。

系统管理页提供本地 PRoot 与 SSH 后端选择、连接档案列表，以及新增、编辑、移除连接。点击档案设为主系统，会话列表不添加本地/云端标签。移除仅删除应用保存的配置与凭证，不删除服务器文件；已建立的会话应结束后重新选择环境。密码、私钥和口令加密保存于 Android 不备份目录，不进入模型上下文。

当前提供命令、后台进程、SFTP 文件操作、协议子进程与底层 SSH PTY。原生终端页面继续使用本地 Linux，尚未提供远程终端渲染。远程下载、输出产物及构建脚本绑定适配器暂缺，相关工具明确报错；可按现有审批策略用远程命令执行服务器已有的构建工具。Android 宿主、浏览器及手机特权工具仍作用于手机。

停止远程进程先发送 TERM，必要时 KILL，等待退出确认；未确认则保留资源并报错，允许重试。网络断开或自行脱离 SSH 会话的后代进程无法保证被回收，服务器本身仍负责进程权限与生命周期。

`SshRemoteIntegrationTest` 使用本机临时 SSH/SFTP 服务验证密码与加密 RSA 私钥、认证前指纹校验、文件路径边界、读写编辑、stdout/stderr 与退出码、超时和后台停止。测试不连接真实远程服务器，不调用模型；Android 真机网络、厂商密钥库与服务器兼容性仍需设备验收。

## 首页、系统状态与工坊

这三个入口依据同一个主系统选择显示内容。SSH 模式下不创建本地页面的 ViewModel，也不读取手机指标或项目列表；切换主系统或修改连接档案会销毁旧页面的在途请求、指标和编辑状态。网络失败显示远程连接错误，不回退显示手机数据。

首页及系统状态从远端 /proc、uname、/etc/os-release 和工作目录所在文件系统采集发行版、架构、内核、内存、存储、负载、运行时间与当前用户可见进程数，每 15 秒刷新，页面不可见时停止订阅。系统状态中的手动命令在指定服务器的工作目录执行，认证凭证回显会遮蔽。

远程工坊将配置的工作目录下非隐藏子目录作为项目，支持新建项目目录、SFTP 目录浏览和 1 MiB 内 UTF-8 文件编辑。保存前检查文件是否被外部修改，替换沿用远程原子写入和路径边界；不注册到本机 Room 项目表，不触发手机的模板或构建流程。原生终端页面、完整模板/导入/构建/签名管线仍是本地功能，远程工坊不显示这些本地操作。

UI 连接获取使用仓储锁内的配置/凭证快照，防止编辑档案时混用旧主机与新凭证；失败的资源清理保留到下一次访问重试，同一连接档案的 UI 操作串行执行。

## 能力矩阵（本地 PRoot / SSH 远程）

UI 与提示按能力位判定，不按 `backend == "ssh"` 分支。能力位复用 `ExecutionEnvironment` 既有槽（`artifacts` / `downloads` / `buildBindings` / `supportsSharedLocalServices`），不新造命名；远程环境未覆写这些槽，即取接口默认值（`null` / `null` / `null` / `false`）。

| 能力 | 本地 PRoot | SSH 远程 | UI / 行为 |
| --- | --- | --- | --- |
| 命令执行、文件读写编辑 | ✅ | ✅（SFTP，限远程工作区） | 会话固定执行环境 |
| 输出产物 `artifacts` | ✅ | ❌（null） | 相关工具明确报错 |
| 下载 `downloads` | ✅ | ❌（null） | 相关工具明确报错 |
| 构建脚本绑定 `buildBindings` | ✅ | ❌（null） | 相关工具明确报错 |
| 共享本地服务 `supportsSharedLocalServices` | ✅ | ❌（false） | 构建 / 子智能体等仍绑本地的服务禁用 |
| 存储挂载（PRoot `-b`） | ✅ | ❌ | 挂载页禁用交互并提示「仅本地生效，不同步到服务器」 |
| 原生终端渲染 | ✅ | ❌（未实现） | 终端页仍为本地；远程终端渲染待做 |
| 发行版安装 / 多系统管理 | ✅ | ❌ | 系统管理页的本地系统条目仅对本地生效 |
| 插件 / 底层工具安装（llama.cpp、QEMU 等） | ✅ | ❌ | 插件中心安装入口停用；安装类调用被拦截并提示「仅本地生效」 |

MCP STDIO 工具是「全局配置 + 按执行环境执行」：配置仍全局一份，执行跟随会话绑定的环境。因此 STDIO 的 `command` 必须在服务器上已存在——远程环境下先探测 `command -v`，缺失时健康检查返回「该 MCP 的可执行文件 `x` 在远程 `<host>` 上不存在」，而不是静默启动失败后只表现为超时。
